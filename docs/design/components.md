# Компоненты и состояния
Эта спецификация задаёт внешний вид и поведение; компонентов в коде здесь нет.

## Шапка
Имя «Сергей Федоренко» в две строки, Manrope 28/26 px desktop, 22/21 mobile, weight 700. Справа «Проекты», «Курсы», «Для бизнеса», «Обо мне» и действие «Обсудить задачу». Активный раздел подчёркнут тонкой линией; цвет не единственный признак.

На mobile — имя и кнопка «Меню». Панель занимает доступную ширину; закрытие подписано, Escape закрывает, фокус возвращается к кнопке. Для клавиатуры предусмотрена ссылка «К содержанию». Высота зон нажатия минимум 44 px.

## Кнопки и ссылки
Основная: высота не меньше 48 px, горизонтальный padding 24, радиус 10 px, подпись 16/600; на mobile при необходимости полная ширина. Вишнёвая на светлом/тёмном, молочная на вишнёвом. Тёмный фон требует светлой границы.

Вторичная: текстовая ссылка с подчёркиванием и стрелкой. Стрелка дополняет понятную подпись. Hover не сдвигает окружающую вёрстку. Focus видим независимо от hover. Disabled — текстовое объяснение рядом, если действие нужно для маршрута; недоступный просмотр не маскировать рабочей кнопкой.

## Строка проекта
Номер 01–04, рубрика отрасли, полное русское название, описание 1–2 предложения, действия. Слева текст, справа крупный настоящий экран или предметная композиция. Пропорция 5/7 либо 6/6 колонок; следующий проект может менять расположение.

Основное действие при готовой витрине «Открыть приложение», второе «Подробнее о проекте». В текущем проекте наполнения витрины не готовы к публикации: пока задаётся дизайн и сценарий. Не показывать статусные бейджи «Demo», «Демо», «Prototype» и имена репозиториев.

Экран системы размещения и CRM показывать в широком окне; ресторанное меню — в телефоне; уроки — в широком окне с возможностью переключить роль/сценарий только при реализации этого действия.

Mobile: номер/рубрика → заголовок → описание → экран → действия. Высота строки по содержимому. Никаких обрезанных названий.

## Строка программы
Номер, название, аудитория и понятный результат. Первая программа может быть раскрыта, остальные компактнее. Клик по «Посмотреть программу» ведёт к содержанию программы, а не неожиданно к форме. В проекте всех трёх программ нет подтверждённых дат и стоимости.

## Кейс
Заголовок → задача → маршрут пользователя → экран с просмотром → 3–5 возможностей → особенности решения → обсуждение похожей задачи. Одна колонка текста и крупные вставки интерфейса. Ограничения конкретной функции объясняются рядом с ней; инженерный реестр остаётся служебным.

## Оболочка просмотра
До активации — достоверный экран и явная кнопка. После — заголовок приложения, «На весь экран», «Открыть отдельно», «Закрыть». Контролы всегда снаружи встроенной страницы. У окна видимая граница и стабильный размер. Название встроенной страницы доступно скринридеру.

Состояния: обложка, загрузка, работа, ограниченный доступ, ошибка, полноэкранный просмотр. Подробности и реальные ограничения — в [сценарии просмотра](../planning/embedded-viewing.md).

## Контактная секция
Короткий заголовок, одно предложение, действие «Написать в Telegram». Допустим выбор контекста «Обучение», «Разработка», «Выступление» только если он имеет рабочий маршрут. Новую форму с фиктивным подтверждением не проектировать. В текущем сайте предусмотрен прямой контакт.

## Материалы и практика
Материалы — редакционный список: тема, краткое обещание содержания, действие «Читать». Статья — широкие поля, читаемая колонка, короткие подзаголовки, один следующий шаг. Практика — последовательные шаги с ясным прогрессом, без чат-интерфейса ради декоративного сходства с ИИ.

## Фотографии и видео
Резервировать место под реальные материалы отдельными сценами с подписью; до получения файла блок можно убрать. Не публиковать серые плейсхолдеры «Скоро фото». Видео начинается по действию пользователя, имеет обложку и субтитры. Никаких автозапусков со звуком.

## Проверка будущей реализации
Клавиатура и видимый фокус; отсутствие горизонтального скролла при 320 px; увеличение текста до 200%; альтернативный текст по смыслу; снижение движения; точное соответствие подписи действию. Полную доступность приложения внутри iframe проверять отдельно от оболочки.
