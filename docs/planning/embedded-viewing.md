# Просмотр приложений внутри сайта
Рабочая спецификация · 27.10.2026 · Не реализовано в этой итерации.

## Результат для посетителя
На странице проекта человек нажимает «Открыть приложение» и работает с настоящим интерфейсом, оставаясь на сайте. Внешняя ссылка — дополнительный выход при ограничениях среды. Статическая обложка не выдаётся за работающее приложение.

В текущих растровых макетах телефон — изображение. Для будущего сайта выбран объёмный корпус с отдельным живым HTML-экраном. Фотография телефона или видео не заменяют этот экран.

## Телефон
Презентация: умеренная перспектива, металлическая рамка, вишнёвая подставка, настоящий экран меню. Визуальный ориентир углов — около −10° по Y и 6° по X; это проектная настройка, уточняется по макету.

Активация: наклон сводится к нулю за 480 ms, экран становится достаточно крупным для управления, декоративное движение прекращается. После закрытия возвращается исходная композиция.

Полноценный 3D-вариант: геометрический корпус и совмещённая HTML-поверхность экрана. Более лёгкий вариант: слои корпуса с CSS-перспективой и живым iframe. Второй даёт объёмную подачу, но не называется полноценной геометрической 3D-моделью. Выбор реализации и производительность проверяются на следующем этапе; сейчас закреплены внешний вид и поведение.

На mobile предпросмотр не перехватывает скролл. После активации — окно по ширине экрана, при необходимости полноэкранная область с постоянной кнопкой закрытия. Маленькая рамка телефона внутри телефона не нужна.

## Состояния
| Состояние | Что видно | Что можно сделать |
|---|---|---|
| Обложка | Реальный экран и название | Открыть приложение |
| Загрузка | Стабильная область и короткая подпись | Закрыть, открыть отдельно |
| Работа | Настоящий интерфейс и панель оболочки | Использовать, развернуть, закрыть |
| Долгая загрузка | Пояснение без ложного диагноза | Открыть отдельно |
| Известный вход/запрет | Честное пояснение, описание проекта | Перейти к описанию или открыть отдельно |
| Ошибка | Короткий текст | Повторить, открыть отдельно |
| Закрытие | Возврат к обложке | Фокус на исходной кнопке |

Страница не может надёжно определить готовность чужого приложения только по загрузке iframe. Для управляемой витрины желательно явное сообщение готовности от приложения с проверкой origin и ожидаемого источника сообщения. Без него использовать осторожный текст о загрузке и постоянный внешний выход. Не угадывать «сервер упал» по пустой области.

Клавиатура: фокус входит в активный просмотр осознанно; закрытие всегда достижимо. В полноэкранной модальной оболочке фокус ограничен оболочкой, но iframe должен оставаться доступным. Escape внутри чужого документа может не дойти до родителя — кнопка закрытия снаружи обязательна.

| Продукт | Наблюдение 27.10.2026 | Вывод |

Точная связка deployment → commit для этих четырёх адресов не установлена. Нельзя ставить отметку «актуально» по HTTP 200.

## Как подготовить рабочую витрину на следующем этапе
1. Зафиксировать выбранную ветку и commit для каждого приложения.
2. Подготовить отдельную презентационную среду с разрешёнными материалами и данными. Для уроков — свой учебный набор; для CRM — изолированный рабочий маршрут.
3. Установить постоянный адрес без входа в аккаунт владельца. Доступ к рабочим кабинетам не открывать ради портфолио.
4. Разрешить embedding только нужным доменам портфолио в этой среде. Согласовать CSP приложения и родительской страницы; учесть X-Frame-Options. Общую защиту рабочих приложений не отключать.
5. Проверить сценарий из обычного браузера без сохранённых сессий, затем из реального домена портфолио.
6. Пройти действия в каждом сценарии, включая закрытие, повторное открытие, мобильный режим и отсутствие настоящих внешних отправок в тестовом контуре.
7. Только после этого включить «Открыть приложение» и указать проверенный URL в реестре.

Это перечень будущих работ, не поручение менять другие проекты в текущей сессии. Прокси для обхода ограничений доступа не предусмотрен.

## Проверяемые критерии
- Работает в чистой сессии, без Vercel SSO и аккаунта автора.
- Показана версия с зафиксированным commit; описания соответствуют реально доступному сценарию.
- Внутри сайта работают переходы, ввод и прокрутка, если нужны для сценария.
- Реальные пользователи и их материалы не раскрываются.
- Состояния ожидания и ошибки не превращаются в бесконечный спиннер.
- Полноэкранный режим не теряет возможность закрытия.
- Режим reduced motion сохраняет весь сценарий.
- При запрете iframe есть рабочий выход; сайт не обещает встроенную доступность, пока её нет.

## Основание технических ограничений
Внешняя страница сама определяет разрешённых встраивающих родителей через [CSP frame-ancestors](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors). Возможности и ограничения вложенного документа описаны в [справке iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe). Наблюдения по приложениям и исходникам — в [реестре](source-register.md).
